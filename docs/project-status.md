更新于 **2026-10-23**。目标是让 Switch 上的远程体验逐步接近原版 UU 的易用性、流畅度与操作完整度。当前优先完善日常使用流程、默认设置、界面和说明；Lite/标准机解码耗时对齐与原生 IPv6 研究暂时暂停。

“已实现”表示代码有实际处理路径；“真机反馈”表示收到过对应场景的测试结果；“编译/安装通过”只证明产物和文件部署，不证明完整功能正确。下面按这个标准记录。

## 已实现并有真机使用记录的主链路

| 功能 | 当前结论 | 仍需注意 |
|---|---|---|
| 连接官方 UU 电脑端、桌面/游戏串流 | 主链路已实际使用 | 依赖账号、电脑在线、网络与服务端兼容性 |
| H.264 与实验性 H.265 | H.265 已有真机串流和改善反馈 | 仍需覆盖不同电脑/驱动/场景，不能保证所有主机表现一致 |
| NVDEC、Deko3D NV12 导入与映射缓存 | 已实现并有多轮流畅度、延迟改善反馈 | 存在回退路径，不宣称全链路绝对零拷贝 |
| RTP/RTX 组帧、NACK 补包及参考帧恢复 | 已实现；早期花屏问题在后续测试中消失 | 不能由此推定所有卡顿或网络异常已解决 |
| 播放调度、缓冲、垂直同步 | 已实现；多轮测试反馈更流畅 | 源端帧率、显示帧率和解码能力需要分别判断 |
| LAN IPv4/公网 IPv4 UDP 路径与地址诊断 | 已有实际连接及路径记录 | 仍可能路径切换；不能只看 P2P 标签判断是否局域网 |
| 动态码率与早期码率上限反馈 | 有实际设置/统计记录 | 当前 UI 以画质档位为入口，旧版独立上限教程已过时 |
| 原生界面、网络详情、可选实时统计 | 已用于迭代测试 | 接收器需另行配置，不能把离线预览当真实数据 |

## 已实现，仍需专项验证或回归

| 功能 | 实现情况 | 待验证点 |
|---|---|---|
| 登录会话保存、退出账号清理 | 已实现 | 会话过期、保存失败、跨更新恢复和反复启动 |
| 电脑在线/离线判断 | 已按原始接口 `CONNECTED` 解析修正，手动刷新 | 不同设备/共享电脑和状态变化；不保证列表实时推送 |
| 键鼠方案一/二、长按 − 切换输入 | 已实现 | 组合按键释放、切换边界、休眠/断连恢复 |
| Xbox 虚拟手柄及位置/字母映射 | 已实现，按实验功能提供 | 电脑驱动、游戏识别及 ABXY 端到端验证 |
| 手机式触屏鼠标、触摸板、滚动/缩放 | 已实现 | 拖动、双指、菜单遮挡及不同画面比例 |
| 原生多点触控 | 已有最多 10 点、稳定编号、取消处理 | 电脑是否正确注入、应用如何解释、快速触点替换；不能仅看发送成功 |
| 自动重连 | 已有有限次数的重试与取消处理 | 断网、电脑重启、账号失效和反复连接的覆盖 |
| Windows 快捷操作 | 已接通，三项危险操作保留确认 | 不同电脑版本和权限环境的执行结果 |
| 安全页远端设置 | 自动锁屏、电脑静音/恢复已有请求 | 电脑端实际执行和结束恢复效果；自动解锁未支持 |
| v57 品牌、图标、首页提示与常驻浮层 | 编译、原生预览和 Lite 安装回读通过 | 本轮真实屏幕/触屏/串流体验反馈 |

## 未完成或未确认互通

| 项目 | 当前状态 | 下一步依据 |
|---|---|---|
| 所有 FPS/画质变化都不断流 | **未解决**；历史测试多次回退重连 | 评审 PR #3，并用电脑实际编码/接收帧率验证；应答成功本身不够 |
| TURN TCP/TLS | 适配已编译，**真实中继互通未确认** | 分别验证 UDP/TCP/TLS、失败回退与退出清理 |
| Switch 原生 IPv6 | **未接通，研究暂停** | 独立研究已有接口查询和被动接收证据，尚无端到端 IPv6 串流；没有把系统模块、内核修改或网关方案作为完成品交付 |
| IPv6/局域网/公网全自动最优选路 | **未完成** | IPv6 尚不可用，现有候选排序不等于已达到原版所有选路行为 |
| Lite 与标准机一致低解码耗时 | **未解决，暂缓** | Lite 曾降到约 2–4 ms，但动态波动仍大于另一台主机；不归因于机型国别或网络而缺乏证据 |
| 完整原版 UU TV/手机版体验 | 持续完善 | 前端、手柄切换、触屏与协议兼容需要逐项验收，不是逐页照搬即可完成 |
| 自动解锁、完整中文输入 | **未支持** | 自动解锁在 UI 禁用；当前屏幕键盘发送范围有限 |

## 本轮之后的工作顺序

1. 收集 v57 的真机反馈：登录保存、在线状态、操作提示、图标、常驻信息和更新后的版本识别。
2. 逐项验证输入链路：两套键鼠方案、Xbox 布局、长按切换、触屏模式和菜单输入隔离。
3. 审核在线 FPS 的后续改动，再进行 30/60 帧切换实测；不以本地目标数字代替电脑端实际变化。
4. 按真实网络环境验证 TURN TCP/TLS 和重连边界。
5. 在重新安排后继续 IPv6 与两机解码差异研究；保留现有资料，不反复进行没有新假设的采集。

新功能进入“完成”前，应有对应操作路径、明确版本、检查记录和必要的真机结果。阶段性成果、已知问题及暂停项持续写入本页与[更新记录](../CHANGELOG.md)。
