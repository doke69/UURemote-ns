# YOUYOU远程使用手册

对应本地测试候选 **v0.1.57**，更新于 2026-10-23。公开主分支和本地测试包的区别见[项目状态](project-status.md#版本与发布状态)。本文描述已实现的操作，不表示所有电脑、游戏和实验功能均已通过验证。

## 启动、登录与连接

### 准备和启动

电脑需安装官方 UU远程、登录账号并保持在线。Switch 需具备运行 homebrew 的环境，并能连接网络；首次排查建议让电脑和 Switch 连接同一路由器。

从 hbmenu 启动时使用完整应用模式，通常按住 **R** 启动一个游戏进入 hbmenu，再启动本程序。只打开相册可能进入“小程序模式”，可用资源不同，不能拿这种启动方式比较串流性能。已有桌面启动入口时，还需确认它指向当前程序文件。

应用文件路径为 `switch/UURemote-ns/UURemote-ns.nro`。不要仅凭旧入口图标判断版本，应查看程序里的版本号。

### 登录

- **扫码登录**：使用手机官方 UU远程 App 扫码，在手机上确认。
- **短信登录**：切换登录方式，填写区号、手机号，获取并填写验证码。按页面提示等待重发时间。
- **已有登录**：程序会尝试恢复本地会话；会话有效时无需每次扫码。
- **登录失效、二维码过期或取消**：根据提示重新生成或重新登录。更新应用不等于续期官方账号会话。

### 首页与电脑列表

1. 使用首页“刷新”获取最新设备状态。当前支持手动刷新，不保证列表实时推送。
2. “切换设备”用于选择电脑；选择后回到首页，点击“进入桌面”。
3. 当前只把服务返回的明确在线状态 `CONNECTED` 显示为在线，其余按离线处理。在线也不等于已经获得控制权，实际连接仍可能受账号、共享权限、电脑休眠或网络影响。
4. 加载中或离线设备不能按正常在线电脑连接。先确认电脑端在线，再刷新，不需要反复退出账号。

未登录进入登录页；有有效会话进入首页；连接成功后进入串流。退出串流回到首页，退出账号则清除本地登录会话。

## 按键与输入模式

**先分清三个层次：本地菜单、键鼠映射、手柄直连。** 两套键鼠方案与两种 Xbox 布局是不同设置，不能互相替代。

### 最重要的两个键

| 操作 | 键鼠映射模式 | 手柄直连模式 |
|---|---|---|
| 长按 **−** | 切到手柄直连 | 切回键鼠映射 |
| 按一下 **＋** | 打开/收起本地串流菜单 | 发送 Xbox Start/Menu |
| 长按 **＋** | 不需要长按，按下就打开菜单 | 打开本地串流菜单 |
| 按一下 **−** | 方案一发送 Windows 键；方案二发送 Tab | 发送 Xbox Back/View |

长按 − 是程序自己的切换操作，不会同时把短按操作发给电脑。切换模式、打开菜单时会释放已有远端输入，避免键鼠或手柄卡在按住状态。

### 本地菜单

本地菜单使用 Switch 的 **A 确认、B 返回**，方向键选择，也可以直接触屏点选。这个约定不会因 Xbox 布局设置而交换。进入菜单后，当前菜单操作不再同时控制远端游戏。

### 键鼠映射：方案一

默认方案。适合直接操作桌面、窗口和浏览器。

| Switch 操作 | 电脑收到的操作 |
|---|---|
| 左摇杆 | 移动鼠标 |
| 按下左摇杆 L3 | 打开本地屏幕键盘 |
| 右摇杆 | 方向键 |
| 按下右摇杆 R3 | 显示桌面，Win+D |
| A / B | Enter / Esc |
| X / Y | 鼠标左键 / 鼠标右键 |
| L / R | Alt / Tab |
| ZL / ZR | 滚轮向上 / 向下 |
| 方向键上 / 下 | Ctrl / Shift |
| 方向键左 / 右 | Backspace / Delete |
| 按一下 − | Windows 键 |
| ＋ | 打开串流菜单 |

### 键鼠映射：方案二

把鼠标和滚轮放在相反摇杆上，并使用扳机操作鼠标左右键。

| Switch 操作 | 电脑收到的操作 |
|---|---|
| 右摇杆 | 移动鼠标 |
| 左摇杆上下 | 滚轮 |
| 按下左摇杆 L3 | 打开本地屏幕键盘 |
| 按下右摇杆 R3 | Shift |
| A / B | Enter / Esc |
| X / Y | 空格 / Backspace |
| L / R | Ctrl / Alt |
| ZL / ZR | 鼠标右键 / 鼠标左键 |
| 方向键 | 对应电脑方向键 |
| 按一下 − | Tab |
| ＋ | 打开串流菜单 |

在“外设 → 手柄设备 → 键鼠映射方案”选择方案并应用。方案一/二仅改变键鼠映射，不改变 Xbox 手柄直连布局。

本版本 L3 在键鼠模式打开键盘；R3 按当前方案执行显示桌面或 Shift，不再作为网络信息快捷键。网络详情请从“更多”进入。

### 手柄直连：Xbox 布局

这是实验功能，需要电脑端和游戏识别到虚拟手柄。切换到此模式后，摇杆、方向键、肩键和扳机发送手柄输入；＋/− 的短按和长按区别见上表。

Switch 与 Xbox 的 ABXY 位置不同。“外设 → 手柄设备 → Xbox 按键布局”提供：

| Switch 实体键 | 按位置，默认 | 按字母 |
|---|---|---|
| B，下方 | Xbox A | Xbox B |
| A，右方 | Xbox B | Xbox A |
| Y，左方 | Xbox X | Xbox Y |
| X，上方 | Xbox Y | Xbox X |

按位置适合按游戏里的物理位置操作；按字母适合希望“屏幕提示 A，就按 Switch A”的用法。无论选择哪一种，本地菜单仍使用 Switch A 确认、B 返回。

## 触屏

菜单可直接点选。串流画面里的触屏方式在“外设 → 触屏操作”选择，且与手柄/键鼠输入模式独立。

### 鼠标：直接指向

手指接触的位置对应远端鼠标位置。轻点为左键，移动手指可按住左键拖动，适合直接操作窗口、图标。

### 鼠标：触摸板

屏幕像笔记本触摸板，滑动是相对移动鼠标；手指离开后，鼠标保持在原位置。轻点左键，长按后移动进行拖动。

上述两种鼠标方式共用以下手势：

| 手势 | 行为 |
|---|---|
| 单指轻点 | 左键点击 |
| 长按并移动 | 左键拖动 |
| 双指轻点 | 右键点击 |
| 双指同向滑动 | 滚动 |
| 双指捏合 | 本地串流画面缩放，最多约 3 倍 |
| 重置画面缩放 | 恢复原始显示比例 |

捏合缩放改变的是 Switch 上显示的画面，不会提高电脑编码分辨率，也不是向电脑发送应用缩放手势。

### 平板多点触控，实验功能

此模式发送原生触点快照，最多处理 10 个触点，由电脑端和应用决定如何响应。它与鼠标手势模式互斥：开启后，不再由客户端把双指动作解释为滚轮或本地缩放。

当前代码在没有保存过偏好时默认选择平板多点触控；这不代表它已完成所有应用的兼容验证。需要稳定鼠标行为时，主动选择“鼠标：直接指向”或“鼠标：触摸板”。菜单能点选，也不能证明 Windows 已正确处理原生多点触控。

## 串流菜单与设置

| 入口 | 主要内容 |
|---|---|
| 串流菜单 | 退出串流；键盘、声音；显示、安全、外设、更多、Windows 快捷操作 |
| 显示 → 画质与帧率 | 30/60 帧、画质档位、播放缓冲 |
| 显示 → 画面设置 | 分辨率、H.264/H.265、垂直同步 |
| 外设 | 手柄模式、键鼠方案、Xbox 布局、触屏方式、键盘、鼠标速度 |
| 更多 | 详细网络信息、常驻网络信息开关、运行统计 |
| Windows 快捷操作 | 显示桌面、任务管理器、切换窗口、锁定桌面、重启电脑、关机 |
| 账号 | 重新登录、关于、退出账号 |

设置项按当前页面选择应用，不是每个页面都有统一的“保存”步骤。设置应用中先等待当前请求结束，避免连点。

### 默认值和画质

以下是**新配置**的默认值，升级保留已有配置：

| 项目 | 默认值 |
|---|---|
| 分辨率 / 目标帧率 | 1280×720 / 60 FPS |
| 画质档位 | 高清 |
| 垂直同步 | 开启 |
| 播放缓冲 | 8 ms |
| 键鼠方案 | 方案一 |
| 视频编码 | H.264；保存过 H.265 的继续使用原选择 |

画质有“自动、省流、清晰、高清、原画”五档。档位中的带宽说明是参考值，实际动态码率取决于内容和链路；静止桌面码率很低不等于设置失效。可选分辨率为 540p、720p、1080p；播放缓冲菜单提供 0、8、16、24、35 ms。当前界面没有独立的“码率上限”菜单，不要沿用早期版本的“第六项设为 10 Mbps”教程。旧配置中保留的码率上限仍可能影响实际结果。

**播放缓冲**是播放队列的等待预算，不是网络 RTT。调低可减少排队等待，但网络抖动时更容易卡顿；调高能吸收部分抖动，也可能增加操作延迟。垂直同步控制显示时序，不会把电脑本身低于 60 帧的内容变成 60 帧。

FPS、画质和分辨率已有在线设置请求，但在当前测试版本中仍可能回退重连；切换编码也可能重连。出现短暂重新连接不等于设置一定失败。不能仅凭“请求成功”判断电脑编码器真的改变了 FPS，应结合实际接收/解码数据。

### 键盘、声音和安全

屏幕键盘当前发送支持英文、数字和空格，不是完整的中文输入法。开启声音、选择音量属于 Switch 的播放设置；电脑端静音属于另一项远端设置。

安全页中，自动解锁目前不支持。自动锁屏、电脑静音和结束后恢复声音已有请求实现，但电脑端实际效果仍需验证，不能当作一定生效的保证。

### Windows 操作确认

- **直接执行**：显示桌面、任务管理器、切换窗口。
- **确认后执行**：锁定桌面、重启电脑、关机。

这些操作作用于当前连接的电脑。重启或关机会影响串流和电脑上未保存的工作。

## 网络信息怎么看

“更多”可以查看详细网络信息，并打开“常驻网络信息”。v57 的常驻浮层贴在右侧，带半透明底，只显示四行数据：

1. 局域网或公网。
2. **实际显示帧率**与视频码率。
3. **RTT 往返延迟**与视频初传缺口比例。
4. 解码耗时与 H.264/H.265 编码格式。

RTT 不是单向延迟，也不是完整的按键到屏幕延迟。初传缺口不等于补包之后最终丢帧率；RTX 可以补回部分包。详细运行统计中的接收、解码和显示 FPS 也不是同一个数字，源游戏或电脑采集帧率会影响它们。

未知或尚未取得的数据应理解为未知，不能当作零。P2P 可能走公网；只有明确的私网路径才能据此判断局域网。`srflx`、`prflx` 类型本身不代表 TURN 中继。当前没有完成 Switch 原生 IPv6，不能把 IPv4 连接解释为已经实现 IPv6 优先。

## 退出、更新和文件

- 结束使用：打开串流菜单，选择退出串流并确认，回到首页。
- 更换账号：通过账号页退出或重新登录；退出账号会清除本地会话。
- 更新程序：先退出应用，备份原 NRO，再替换当前 NRO；保留 `switch/UURemote-ns/` 内的配对与设置，不要整目录删除。
- Lite 与标准机目前使用同一条应用开发线；同一个安装包不意味着两台主机的实际解码耗时必然相同。

配置目录为 `sdmc:/switch/UURemote-ns/`：

| 文件 | 作用 |
|---|---|
| `session.json` | 登录会话；包含敏感信息，不应公开 |
| `config.ini` | 画质、帧率、编码、播放缓冲等设置 |
| `ui-state.json` | 界面偏好、键鼠方案、Xbox 布局、触屏选择等 |
| `connection.log`、`diag/` | 连接和诊断资料，反馈前需检查并脱敏 |
| `telemetry.ini` | 可选局域网诊断回传设置，不是正常使用的必需项 |

输入模式切换与保存的映射方案不同；不要把所有临时状态都视为重启后必然恢复。未配置实时诊断接收器时，不应期待电脑自动收到统计。

## 常见问题

**每次都要扫码？** 先确认一直启动的是同一路径和版本，且没有清理会话文件；账号退出、会话过期或保存失败都会要求重新登录。保留报错信息，不要直接删除整个目录。

**电脑没出现、离线或无法进入？** 确认电脑端账号、网络及在线状态，手动刷新。如果列表明确在线但实际连接失败，记录界面错误和当前版本，再查看连接阶段日志。

**A/B 与游戏提示相反？** 先判断是在本地菜单还是远端游戏；进入手柄直连后，可切换 Xbox 的按位置/按字母布局。键鼠方案不能解决 Xbox 字母布局问题。

**触屏点不到或没有鼠标行为？** 查看是否选中了实验性平板多点触控。需要鼠标时改选直接指向或触摸板；电脑应用也可能不支持原生触点。

**为什么改帧率会重连？** 当前在线设置仍有回退路径。相关改进在待合并 PR 中，尚不能视为已解决。

**卡顿一定是 Wi-Fi 丢包吗？** 不一定。需要区分源端 FPS、接收缺口、补包、解码、显示和播放缓冲；静止场景低码率也不是故障。Lite 与标准机的耗时差异仍待研究。

**为什么没有 IPv6？** 当前未接通。独立 Inspector 的监听/查询结果和研究方案不等于已实现 IPv6 串流。

反馈时请给出版本、机型、启动方式、编码/分辨率/FPS/播放缓冲、发生步骤和是否可重现。截图尽量避开二维码、账号、完整地址；不要公开会话、密钥或整个 SD 卡备份。
